# Chat agent ("Ask" tab, `POST /api/chat`)

**Status: built and tested with a scripted fake model; blocked for real use until `ANTHROPIC_API_KEY` and `ANTHROPIC_MODEL` are set** (the API returns 503 and the Ask tab says so). Never run against the real model yet, so its answers are untested.

- **Loop** (`backend/app/agent.py`): a manual tool-use loop over the Anthropic Python SDK with streaming, up to 8 tool rounds, conversation history kept in `core.user_chat` (user data, backed up) so follow-ups work. Tool results are wrapped as data ("not an instruction"); the system prompt carries the hard rules (sources and confidence in every claim, say what input is missing, never invent numbers, hazards are information only for conversions, never say land is available to buy, screens not planning advice, read-only, no promise words). Refusals, truncation and the step limit are reported to the owner, not hidden.
- **Tools** (`agent_tools.py`): `describe_schema`, `run_sql`, `search_rules`, `site_info`, `listings_search`. No write or send tool exists. `run_sql` accepts one SELECT over `core.*`/`analytics.*` (parsed with sqlglot; DML/DDL, multiple statements, row locking, `raw` and system schemas, cross-database references, table functions and dangerous functions are rejected; 26 attack cases tested), is capped at 200 rows, and runs as the `ai_readonly` role (SELECT on core/analytics only, read-only, 15 s timeout; tested to be unable to read `raw`, write, create, or read chat history).
- **Not built (LATER):** `fit_units`, `subdivision_yield`, `feasibility` (development finder), `map_highlight`, `consent_path`, Māori land screening. The agent is told so.
- **Model**: set `ANTHROPIC_MODEL` yourself; nothing is hard-coded. Thinking, forced tool choice and prefill parameters are not used, so current models accept the requests.
- **First real run checklist** once the key is set: ask the four example queries in the spec, check each answer cites its source and tier, and confirm the interpretation line appears.
