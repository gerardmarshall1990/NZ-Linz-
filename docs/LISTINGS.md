# Listings, address matching and verdicts

- **Sources** (`config/listing_sources.yaml`): CSV/manual = live. Trade Me = pending (official API only; terms not yet read or approved; no scraping). realestate.co.nz = blocked (no lawful route yet). Every listing response carries the coverage warning "... not connected: coverage is incomplete".
- **Import**: `POST /api/listings/import` (CSV; flexible headers; `dry_run` default true; `snapshot=true` marks missing listings removed). Identity = source + id, else source + normalised address + unit + type. Rent/bedroom/etc. changes write `core.user_listing_history`; a removed listing that returns is relisted with history. Only structured facts and the link are stored: no description text or photos.
- **Matching**: normalised street, number, suffix, unit, suburb against LINZ addresses, then the parcel containing the address point. Confidence high / medium / low / none with the method stated; low and none go to `GET /api/listings/review-queue`; `PUT /api/listings/{id}/match` fixes them.
- **Property Record**: a high or medium match upgrades bedrooms and bathrooms to DOCUMENTED (source: listing); a CONFIRMED fact is never overwritten.
- **Verdict** (`POST /api/listings/search`, `GET /api/listings/{id}`): GREEN / AMBER / RED / GREY per Part 6.2, with reasons, tier, minimum beds (closed form, cross-checked against brute force in tests), walk-away rent, rent multiple possible, and offer levels at 1.25x, 1.5x and 2x with the ceiling flagged. With the deal inputs unset (today's default) every listing is GREY and the response lists what is needed; a deal-breaker (unit title or cross lease, zone with only non-complying or prohibited related activities, too small, not viable at the asking rent) still shows RED. Natural hazard flags are returned as information and never change a verdict (tested).
- **Beds** for a listing = listed bedrooms, an upper bound until plans show rooms lost to office, communal space and ensuites. Screening retrofit uses `retrofit_cost_per_bed_screening` (blank: your input).
- **Not built yet**: Trade Me API client (blocked on terms), nightly digest and email, saved-search alerts, the map layer and the Site Panel tabs.

## Map and Site Panel (`/`)
Leaflet map with listing dots coloured by verdict and sized by beds, verdict and minimum-beds filters, address search, tap any parcel. Panel tabs: Parcel (zone, overlays, PC120 status, hazards as information only), Listing (verdict, reasons, walk-away rent, offer levels, use listing facts in the Property Record), Rest Home (Property Record, evidence gaps, layout options with DRAFT drawings, compliance, economics, fire brief), Offer (Offer Builder, three modes, proposal pack PDF), My inputs (your assumptions and QS rates, stored in `core.user_setting`, layered over the blank config), Import (CSV with dry run, source coverage, address matches to check). Plans, scale and review is at `/plans?parcel=<id>`. A banner shows source coverage on every view. Tested in headless Chromium at phone width (`tests/test_ui_smoke.py`).
Not built: parcel polygons as a map layer for whole-region browsing (tap-to-identify only), nightly digest, saved-search alerts, shortlists, vector tiles.
